## 镜头 03 · 三大模式总览

**版式**：`comparison` · `triple`

**画面文案**

- title：三大架构模式 · 一张图认全
- subtitle：先建立地图，再逐个拆
- pillars：主从式｜对等式｜层级式（各 2~3 行特征）
- insight：没有「万能架构」· 只有「场景匹配」

**口播**

先把地图画出来。主从式，有一个中心调度，任务拆完分给干活的 Agent，像项目经理带团队。对等式，大家地位平等，靠消息协商、辩论或投票推进，没有固定老板。层级式，上面规划、下面执行，中间还能再套一层主管，适合特别大的任务树。三种没有绝对好坏，关键看你的流程是固定还是发散、要不要强管控。

---

## 镜头 04 · 主从式（Supervisor）

**版式**：`comparison` · `hub`（中心调度 + 执行节点）

**画面文案**

- title：【模式 1/3】主从式 · Supervisor
- subtitle：一个大脑拆任务 · 多个手脚干活
- topology：中心「调度 Agent」+ 搜索 / 写作 / 审核
- insight：流程清晰时要它 · 调度挂了全队停摆

**口播**

主从式最适合流程相对固定的活。比如写调研报告：调度 Agent 先拆成搜索、整理、写稿、审核四步，分给四个专业 Agent，最后汇总。好处是责任清楚、好排查——哪一步错了就定位哪个 Worker。坑也有：调度 Agent 是单点，它理解偏了，后面全白干；而且每一步都要等调度下发，延迟比并行高一些。做客服工单、标准 SOP 流水线，主从式通常最省心。

---

## 镜头 05 · 对等式（Peer / Swarm）

**版式**：`comparison` · `mesh`（环形互联）

**画面文案**

- title：【模式 2/3】对等式 · Peer-to-Peer
- subtitle：无中心 · 协商 / 辩论 / 共享看板
- insight：创意发散时要它 · 协调成本也最高

**口播**

对等式更像头脑风暴会议室。写方案可以让「保守派」「激进派」「成本控」三个 Agent 轮流发言，互相反驳，最后投票或共识合并。没有中心节点，鲁棒性强——坏一个不至于全队瘫痪。但协调成本高，容易聊着聊着跑偏，也就是常说的意图漂移。适合创意生成、策略辩论、需要多角度碰撞的场景。要是你的任务步骤写死在文档里，硬上对等式反而添乱。

---

## 镜头 06 · 层级式（Hierarchical）

**版式**：`comparison` · `tree`（三层树状）

**画面文案**

- title：【模式 3/3】层级式 · Hierarchical
- subtitle：规划 → 分派 → 执行 · 可递归拆子树
- insight：大项目拆子项目 · 每层只盯自己那一级

**口播**

层级式解决的是「任务太大，一层调度看不完」的问题。顶层 Agent 只做全局规划：先拆成市场、技术、运营三条线；每条线再有自己的子主管，继续往下分到具体执行 Agent。LangGraph 的 Send API、CrewAI 的 Manager Agent，本质都是这种思路。好处是能扛复杂项目，坏处是层级一多，状态和接口要设计仔细，不然信息在层与层之间丢字段。企业级多 Agent 平台，很多默认就是层级式。

## 镜头 07 · 选型对照

**版式**：`benchmark`

**画面文案**

- title：怎么选？· 场景对照表
- benchmarkRows：固定 SOP / 创意辩论 / 超大项目 等
- insight：先 2 个 Agent 跑通 · 再谈加人和加层

**口播**

给你一张选型表。流程固定、要强管控、要审计追溯——主从式。需要多角度碰撞、并行探索、去中心化——对等式。任务能拆成大树、子项目各自独立——层级式。工程上我建议：先从两个 Agent 的主从式跑通闭环，验证输入输出 Schema 和共享状态；稳定了再加 Worker 或加层级。别一上来就十几个 Agent 开会，调试成本会把你劝退。

## 镜头 08 · 小结

**版式**：`cards` · `verdict`

**画面文案**

- title：本期小结
- cards：主从 = 项目经理制｜对等 = 会议室制｜层级 = 事业部制
- insight：架构即组织 · 选错了比模型差更致命

**口播**

总结一下。主从式像项目经理带团队，对等式像会议室辩论，层级式像公司事业部。多 Agent 的上限不取决于你堆了多少个 Agent，而取决于架构是不是匹配场景。模型再强，组织乱了也干不成大事——这话上期说过，这期换成架构版。
